# 차별 기능 다섯: 설계 문서 안내

기존 VOD·클립 다운로더와 갈라지는 다섯 기능의 설계와 확정 결정이다(2026-10-16, 기준 origin/master `df454c3` v0.7.0). 이 폴더는 **설계만** 담고 구현은 `plan.md`의 PR 표 순서로 한다. 진행 기록은 `docs/ROADMAP.md`의 "Phase 5 — 차별 기능"이 남긴다.

## 다섯 기능

| 기능 | 한 줄 | 문서 |
|---|---|---|
| ① 편집자 위임 | 스트리머가 앱 설정에서 편집자에게 자기 채널 영상 받기를 맡기고, 편집자는 초대 주소 로그인으로 수락한다(Worker 위임 표 + 셸 판정 + 설정 화면) | `delegation.md` |
| ② 구간만 받기 | 빠른 다시보기에서 시작·끝 시각을 정해 그 구간만 받아 defrag로 일반 mp4로 마무리한다 | `range.md` |
| ③ 내 채널 새 영상·모아 받기 | 본인 채널의 새 영상을 찾아 골라 한꺼번에 받는다. 원장으로 받은 것을 기억한다(수동 먼저, 스케줄러는 뒤) | `backup.md` |
| ④ 채팅 함께 받기 | 영상 완료 뒤 채팅을 받아 편집 프로그램에 넣을 수 있는 자막(ASS·SRT)으로 옆에 둔다 | `chat.md` |
| ⑤ 생방송 녹화 사후 점검 | v0.7.0으로 배포된 생방송 녹화를 코드로 점검한 결과와 고칠 순서(F1~F6). 새 기능이 아니라 fix 묶음 | `live-audit.md` |
| (별건) 허용목록 개방 | 처음 로그인한 채널을 허용목록에 자동으로 넣고 하루 새 채널을 상한(기본 20)으로 묶는다. 다섯 기능과 별개인 배포 정책 변경(2026-10-18) | `allowlist-open.md` |
| (추가) 속도 제한 | 전체 합계·작업마다 두 받기 속도 상한(기본 끔, 받는 중 바로 적용, 최소 1MB/s, 생방송 녹화 제외). 다섯 기능 밖의 추가 설계(2026-10-18) | `rate-limit.md` |
| (추가) 앱 CLI 모드 | 같은 앱 실행 파일의 하위 명령(`download`·`info`·`status`·`login`·`help`)으로 터미널에서 받는다. 같은 로그인 세션·소유 게이트, GUI와는 데이터 폴더 잠금으로 한쪽만 실행, `login`은 앱과 같은 루프백 로그인, Windows는 콘솔 실행 파일 `chzzk-cli.exe`. 명세·사용자 결정 반영(2026-10-18) | `cli-mode.md` |
| (추가) 파일명 토큰 템플릿 | 설정에서 저장 파일명 규칙을 `{date}`·`{channel}`·`{title}` 같은 토큰으로 정한다. 기본은 지금 규칙과 같다(2026-10-18, 결정 표 T1~T8 사용자 결정 대기, 추천 안으로 구현됨) | `filename-template.md` |

그 밖에 경쟁력 개선(2026-10-18, ROADMAP "경쟁력 개선 착수")의 설계도 이 폴더에 둔다: (바) mp4 메타데이터·표지는 `mp4-metadata.md`.

## 읽는 순서

1. `decisions.md`: **확정된 결정**(맨 위 표)과 남은 결정·사용자 실측 표. 다른 문서와 다르면 이쪽이 우선한다.
2. `plan.md`: PR 표(트랙별), 의존 그래프(기능 선행 조건과 머지 순서), 릴리스 지점, Codex 3회차 반영 표.
3. 건드리는 기능의 설계 문서(위 표). 문서 머리의 "상태·확정 결정"이 그 기능에 걸린 결정을 모은다.
4. ⑤를 고칠 때는 `live-audit.md`를 먼저(배포된 동작과의 차이, 재현 순서).

## 설계 문서와의 관계

- 코어는 `docs/design/core.md`, 앱(셸·GUI)은 `docs/design/app.md`, Worker는 `docs/design/worker.md`가 기준이고 **세 문서 모두 끝의 "구현 중 변경"이 본문보다 우선한다**(app.md는 그 절 머리의 "읽는 법" 표부터). 시각·문구·컴포넌트 규칙은 디자인 시스템 `docs/design/system/`(README 결정 표 > foundations > 나머지)이 단일 원천이다.
- 이 폴더의 문서는 위 기준 문서를 대체하지 않는다. 기능을 구현하는 PR은 해당 문서(core.md·app.md·worker.md)의 "구현 중 변경"에 **번호를 붙여** 적고, 번호는 머지 순으로 이어 붙인다(`plan.md` §1: core.md 61 이후, app.md 78 이후, worker.md 105 이후, ADR 0026 이후, D64 이후). 구현이 설계와 달라지면 해당 "구현 중 변경"에 먼저 적고, 설계가 틀렸던 것이면 이 폴더의 문서에도 정정 문단을 남긴다.
- 표기: `파일:줄`은 기준 커밋 `df454c3`에서 연 줄이다(이후 바뀌면 달라진다). **[확인]** 직접 연 줄이 받침 / **[확인: 문서]** 설계 문서의 인용 / **[가정]** / **[실측 필요]** / **[잠정]** 출처 없는 수치(ADR-0009 묶음).
- 조사 원자료(엔드포인트·응답 필드·출처), 근거 확인 표, UX 설계안, Codex 리뷰 원문은 **저장소에 없다**(공개 저장소 규칙: 실제 채널·영상 ID·서명 토큰·내부 동작 조사 내용을 두지 않는다). 문서의 예시 값은 모두 가짜다.
- 사용자 실측(`decisions.md` §2)은 사용자가 직접 돌리고 결과는 범주(된다/안 된다, 일치/불일치)만 `docs/ROADMAP.md`에 적는다.
