# 0001 방향 선택: A 「무색」 뼈대 + B 내용물 + C 문구

상태: 채택(잠정)   날짜: 2026-10-09   관련: D2, D5, D11, D24, D26, D36, README §3-5, README §6-6

## 맥락

디자인 시스템을 새로 세우기 위해 방향 후보 셋을 같은 브리프(D1~D62)와 같은 검증 보고서 여섯 개로 독립 작성했다: A 「무색」(OS의 일부처럼, 색을 지움), B 「작업대」(작업 큐 도구, 조밀, 남보라), C 「또렷한 다정함」(읽기 쉬운 글자, 다정한 문구). 각 후보는 direction.md·tokens.css·목업 HTML 6장을 냈고 판정자가 스크린샷 82장을 보고 점수를 매겼다(judgment). 현재 앱은 `A-VIS-01`~`A-VIS-41`(루트 14px로 모든 토큰이 12.5% 작게, 열 폭 3종, 기준선 3종, 주 버튼 둘, 실패 행 빨강 5겹)의 결함을 안고 있어 어느 후보로 가든 전면 적용이다.

사용자는 근거만으로 갈리지 않는 다섯 가지를 직접 골랐다(judgment §3).

## 결정

**A를 뼈대로 채택한다.** A의 토큰(글자 13/16·12·15·17, 컨트롤 24/28/36, 간격 2~40, 반경 4/6/10/12, 무채색 바탕, 글자용·채움용 강조색 분리, outline 포커스, 모션 100/200/300, 면 단계)과 원칙(P1~P5)이 그대로 `foundations.md`가 된다.

B에서 **내용물**을 옮긴다: 홈 최근 영상(VOD·클립) 목록 + [다시 열기], 붙여넣기 힌트와 [받기 ⌘↩], 카드 "받다 만 파일" 안내, 상태 어휘(건너뜀·원본 바뀜), 아이콘 은유 표, Worker 골격(`theme-color`·skip link·`caption`·`th scope`·"처음 열면 로그인해요"·"막히면"), 설정 계정 행 "허가된 채널이에요".

C에서 **문구**를 옮긴다: 실패 본문 "공간을 비운 뒤 이어받으면 받던 곳부터 이어가요. 받은 부분은 그대로 있어요.", 취소 대화상자 본문, 빈 상태 3단계, "가장 좋은 화질" 꼬리표, "인터넷", Worker 읽기 척도 15/22(`data-scale="reading"`), 헤더 배지(C는 pill이라 불렀다) "비공식 도구"(Worker만).

사용자가 고른 다섯 가지를 그대로 쓴다: 강조색 **파랑**(D5), 헤더 **마크 + 이름**(마크 전까지 이름만, D26·D33), 대화상자 **오른쪽 끝 = 안전 = 채움 = Enter, 파괴는 왼쪽 빨간 글자**(D36, ADR-0005), 앱 본문 **13px**(`--text-body` 하나로 14 전환 가능한 구조, D11), 본문 열 **가운데 최대 800**(D24).

열 800은 두 후보 어디에도 없는 값이다(A 720·B 960). **출처 없음, 절충**이라고 적는다. 720 창에서 꽉 차는 불변식(A)은 유지되고 960 기본 창에서 좌우 80px이 남는다.

## 결과

- `docs/design/system/` 전체가 이 결정의 전개다. README 결정 표 D1~D62 중 D2·D5·D6·D9·D11·D12·D16~D24·D36·D37이 A, D35·D53이 B 골격, D42~D50 문구와 D11 Worker 척도가 C 구조다(judgment §2.4 표).
- A의 결함 여섯(judgment §1.4 A): 비활성 ghost 테두리 특이도, 인라인 `style` 2종, 무리수 행간, 다크 매핑 중복, 랜딩 13px은 `components.md`·생성기·읽기 척도로 고친다(README §6-14).
- B에서 버린 것: 남보라, 반전 다크 주 버튼, 4px 막대, 3px 레일(ADR-0003), 3 OS 테마 토글, 24시간, accent-soft 배너, `!important` reduce.
- C에서 버린 것: 앱 본문 15, 36/44 컨트롤, 헤더 52, 민트 성공색(ADR-0004), 채움 버튼 복수, 아이콘 비례 축소, 8px 막대.
- 적용은 `governance.md` §10의 여섯 단계.

### 재검증 조건

- 첫 사용자 시험(D62, `governance.md` §6)에서 V1~V8을 본다. 특히 V2·V3(대화상자), V4(13px), V5(헤더 이름), V1(완료 색).
- 열 800: 960 창에서 좌우 80px 여백에 대한 불만이 3명 중 2명 이상에서 관찰되면 `--content-max`를 720 또는 960으로 바꾸는 ADR을 쓴다(README §6-6). 토큰 하나라 체계는 깨지지 않는다.
- Windows 실기(README §6-1)에서 13px이 작으면 `--text-body`·`--leading-body`를 14/18로(D11 구조가 이를 위한 것이다).
