# 0004 성공색 없음(잠정)

상태: 채택(잠정)   날짜: 2026-10-09   관련: D10, D35, foundations §2.1·§2.2·§9.1, README §6-5

## 맥락

현재 앱은 `--success`·`--success-soft`(청록 계열)를 두고 완료 상태·배지에 쓴다. 치지직의 브랜드 초록(`#03C75A`, HSL H 146°)과 가까운 초록은 어울림 기준 C1(브랜드 자산 없음: H 140~165°이면서 S ≥ 70% 금지)에 걸릴 위험이 있다. 세 후보 중 A는 초록 토큰을 두지 않았고, B는 H 124°·S 39%(범위 밖), C는 다크 `#55D7BE`(H 168°·S 62%, 경계)·라이트 `#007563`(H 171°·S 100%, 하한에 1°)을 썼다(judgment §1.2 C1 행).

성공색이 있으면 C1 검사가 "범위 안인지"를 색마다 따져야 하고, 완료 아이콘 색이 브랜드색을 떠올리게 할 수 있다. 성공색이 없으면 C1 검사는 "초록 토큰 0개"로 끝난다.

## 결정

**성공(초록) 토큰을 두지 않는다.** `tone`의 값 집합은 `neutral`·`warning`·`danger` 셋이다(`success` 없음, D35). 완료는 세 겹으로 전한다: `check` 아이콘(`--fg-muted`) + "완료" 글자 + 완료 그룹 위치(목록의 완료 그룹으로 이동, 11개 넘으면 접힘). OS 알림·토스트의 완료는 `circle-check` 아이콘 + 문장이다.

이 결정은 **잠정**이다. 재검증 조건에 걸리면 B 후보의 초록(H 124°·S 39%, `#2F7D4B`급)을 **`--success-ink` 토큰 하나**(✓ 아이콘·글자용)로만 더한다. 채움·면 토큰은 만들지 않는다.

## 결과

- `design-tokens` T15: 이름에 `success`가 든 토큰 0개. T9: C1 스캔은 유채색 19개(파랑·빨강·호박)만 본다.
- `vocab.ts` `TONE = ['neutral','warning','danger']`. `design-lint` P1.
- `components.md` Badge·Notice에 성공 톤 없음. Notice의 성공 메시지(예: "복사했어요")는 `tone=neutral` + `circle-check`.
- 기존 `--success`·`--success-soft`·`--kind-*` 색 토큰과 `tokens.test.ts`의 해당 대비 쌍이 사라진다(단계 (a)).
- 뒤집힐 때의 변경 범위: 토큰 1개(`--success-ink`, 라이트·다크 두 값, `contrast.tokens.json`에 4쌍), T15 조건 완화, 아이콘 `check`의 색 한 줄. `tone`에 `success`를 더하지는 않는다(아이콘 색만).

### 재검증 조건

- D62 V1: 5초 과업 "다 받은 영상을 찾아 보세요"에서 **3명 중 2명 이상이 못 찾으면** 위의 `--success-ink` 추가 ADR을 쓴다. 두 회 모두 전원이 찾으면 상태를 `채택`으로 올리는 ADR(표본 "3명 중 3명, 2회")을 쓴다.
- 지원 문의에서 "다 받았는지 모르겠다"가 2건 이상이면 시험을 기다리지 않고 재검토한다(O9).

## 대안과 버린 이유

| 대안 | 버린 이유 |
|---|---|
| B의 초록(H 124°·S 39%)을 처음부터 채택 | C1 검사에 "범위 안의 초록은 허용" 조건이 생겨 단순함이 깨진다. 확인되지 않은 필요(근거 5)에 미리 답하는 셈이다 |
| C의 청록·민트 | 경계값(H 168~171°)이라 C1 하한을 170으로 두면 걸리고, 옛 앱의 청록(182°)과 가장 가깝다(judgment §1.2) |
| 파랑을 완료에도(선택·완료 겸용) | 한 색에 두 의미. "받는 중" 막대도 파랑이라 받는 중과 완료가 같은 색이 된다 |
| 완료 아이콘만 `--accent-ink` | 같은 이유. 파랑 ✓는 "선택됨"(메뉴 항목의 ✓)과 겹친다(foundations §2.3 `--accent-ink` 쓰는 곳) |
