# 0016 Toolbar: 열 안쪽 정렬의 start·end 두 칸

상태: 채택(잠정)   날짜: 2026-10-10   관련: D24, D33, components §2.28, governance §5 단계 3

## 맥락

앱 위 띠(T1~T7 모든 화면의 머리)는 화면마다 왼쪽 요소가 다르다(홈은 앱 이름, 설정은 [←]와 화면 제목). 오른쪽의 계정·설정 아이콘 위치가 화면을 옮겨도 흔들리지 않아야 한다(`A-FEAT-A3`·`A6`).

## 결정

`Toolbar`(components §2.28)를 더한다. `--toolbar-h` 44 띠(`--bg`, 아래 1px `--separator`)이고 스크롤 영역 밖이라 층이 없다. 안쪽은 PageContainer와 같은 `.col`이라 왼쪽 글자 x와 오른쪽 아이콘 상자 x가 열 안쪽 x와 같다(README D24). 왼쪽은 앱 이름 또는 [←] + 화면 제목, 오른쪽은 계정 Menu + 설정 IconButton이다. 앱 마크는 D33이 정해질 때까지 두지 않는다.

(b) 구현의 계약 결정: API는 `start`·`end` snippet 두 칸이다. 앱 이름은 사용처가 `.app-name`, 화면 제목은 `<h1 class="toolbar-title" tabindex="-1" data-focus-container>`로 둔다.

## 근거

| 주장 | 등급 | 출처 | 표본·날짜 |
|---|---|---|---|
| 화면을 옮기면 오른쪽 아이콘 자리가 흔들렸다 | E1 | `A-FEAT-A3`, `A-FEAT-A6` (정적 감사) | 2026-10-09 |
| 툴바 안쪽을 본문 열과 같은 열로 맞춘다 | E1 | README D24 | 2026-10-09 |

최고 등급: E1 / 결정 영향: 작음 / 판정: 채택(잠정)

## 결과

- 바뀌는 곳: components §2.28, `ui/Toolbar.svelte`. 앱 헤더 이행은 (b) 사용처, 화면 구성은 (c)다.
- gate: `frontend`(화면별 구성 표), `design-gallery`(툴바 첫·끝 요소 상자 x = 열 안쪽 x ± 2px).

### 재검증 조건

- 앱 마크(D33)가 정해져 왼쪽 칸에 마크가 들어갈 때 start 칸으로 충분한지 확인한다. 모자라면 새 ADR.

## 대안과 버린 이유

| 대안 | 버린 이유 |
|---|---|
| 화면마다 지역 헤더 | 오른쪽 아이콘 자리가 화면마다 흔들린다 |
| `title`·`back`·`account` 같은 칸별 prop | 화면 종류가 늘 때마다 API가 커진다. 두 칸이면 사용처가 구성한다 |
