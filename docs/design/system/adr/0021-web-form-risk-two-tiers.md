# 0021 웹 폼 위험도 두 단계: 허가 빼기만 확인 페이지, 나머지는 즉시 실행과 멱등 303

상태: 채택(잠정)   날짜: 2026-10-10   관련: D54, D37, D36, web §6.3·§7.2·§7.3, worker.md 구현 중 변경 99, 적용 단계 (e), ADR-0005, ADR-0011

## 맥락

옛 관리 화면은 모든 버튼이 같은 모양이었고 `danger`를 가리지 않고 썼다(`A-WORKER-3.1`). 한편 성공해도 아무 안내 없이 화면만 다시 그려졌고, 이미 처리된 대상을 다시 누르면 404 오류 페이지가 나왔다(g-web G1~G7). 무스크립트 폼이라 클릭 직전 확인을 띄울 수 없고, 확인을 모든 동작에 두면 관리자가 지치고 진짜 위험한 확인이 묻힌다. 위험이 어디에 있는지 정해야 한다.

## 결정

위험도를 두 단계로 나눈다.

1. **되돌릴 수 없고 다른 사람에게 번지는 동작만 확인 페이지를 거친다.** 지금은 [허가 빼기…] 하나다. 허가를 빼면 그 채널로 로그인한 앱과 브라우저가 다음 서버 연결 때 끊기고, 다시 허가해도 끊긴 기기는 새로 로그인해야 한다. 표의 [허가 빼기…]는 링크 버튼(`a.btn`)이고 `GET /admin/<channelId>/disallow`(자격 admin, 로그 quiet)가 확인 페이지를 그린다. 확인 페이지는 상태를 바꾸지 않고(크롤러가 불러도 불변), 채움 버튼 없이 폼 하나(`POST /admin/disallow`, 왼쪽 최종 버튼 [허가 빼기])와 오른쪽 링크 "허가한 채널 목록으로"를 둔다. 최종 POST의 경로와 필드(`csrf`·`channelId`)는 옛 그대로라 CSRF·Origin 검사 순서가 바뀌지 않는다.
2. **나머지(로그인 끊기, 거부 기록 지우기, 허가 추가, 로그아웃)는 즉시 실행한다.** 대신 **멱등**이다. 이미 처리된 대상을 다시 보내면 오류가 아니라 `303` + 일회 알림 `alreadyDone`("이미 처리됐어요.")이다. `404`는 경로 값 형식이 틀린 경우에만 쓴다. 성공 POST는 모두 303(PRG)이고 관리 동작의 성공 알림은 두지 않는다(문구가 없고 표의 변화가 결과를 보인다).

`tone-danger`는 확인 페이지의 최종 버튼에만 있다. 끊기·지우기·허가·로그아웃은 위험 표시가 없는 보조 버튼(`.btn`)이다. 비파괴 "지우기"나 대기 취소는 위험이 아니다(D37). 검증 오류는 별도 오류 페이지가 아니라 400 + 관리 화면 다시 그리기(오류 요약 + 필드 옆 문구)다.

## 결과

- 바뀌는 곳: `routes.ts`(`GET /admin/:channelId/disallow`), `http/admin.ts`(`adminDisallowConfirm`, 멱등 303), `http/admin-view.ts`(`renderDisallowConfirm`, 오류 요약), `http/web-session.ts`·`http/auth.ts`(flash 쿠키로 `seeOther` 보완), `web.md` §6.3·§7.2·§7.3, `worker.md` 구현 중 변경 99, `content.md` §15.3(`confirmDisallow.*`·`alreadyDone`).
- gate: `worker`(vitest: 확인 페이지 폼 1개·`tone-danger` 1개·채움 버튼 0개, 확인 GET이 상태를 바꾸지 않음, 멱등 303 + flash, 400 오류 요약), `worker-e2e`(허가 빼기 흐름에 확인 페이지 한 단계), `design-worker`(`.btn-primary` ≤ 1).

### 재검증 조건

- 관리자가 [허가 빼기…]의 확인 단계를 불편해하거나, 반대로 [로그인 끊기]를 실수로 눌렀다는 보고가 나오면 위험 구분을 다시 본다. 확인: D62 관리자 과업 또는 운영 중 감사 기록의 되돌리기 패턴.
- 위험한 동작이 더 생기면(예: 일괄 삭제) 확인 페이지 대상을 늘리는 새 ADR을 쓴다.

## 대안과 버린 이유

| 대안 | 버린 이유 |
|---|---|
| 모든 파괴류에 확인 페이지 | 즉시 되돌릴 수 있거나 영향이 한 기기뿐인 동작까지 확인하면 확인이 의례가 된다 |
| 확인 없이 즉시 실행 + 되돌리기 | 무스크립트라 지연 삭제·되돌리기 토스트를 만들 수 없다. 끊긴 기기는 되돌릴 수 없다 |
| `confirm()` 대화상자 | 스크립트 금지(CSP), 접근성·스타일 통제 불가 |
| 이미 처리된 대상을 404로 둔다 | 재제출·뒤로 가기·두 관리자의 동시 조작이 오류 페이지가 된다 |
