# 0022 Dock·작업 표시줄 진행 집계: 배치 구성원 기준, 단조, 포커스 없을 때만 Error, 1Hz

상태: 채택(잠정)   날짜: 2026-10-10   관련: D29, platform §8.2·§22 32, app.md 구현 중 변경 67 (마)·73

## 맥락

README D29는 Dock·작업 표시줄 진행을 켠다고 했고 platform §8.2가 집계 표를 적었다. 표는 "배치"를 "대기열이 비었다가 채워진 시점부터 다시 비기까지"라고만 정의해 구현에서 갈리는 곳이 있었다. 일시정지한 작업은 배치에 속하나, 일부 실패한 배치가 끝났는지, 새 작업이 더해져 분모가 커질 때 값이 줄어도 되는지, 앱 시작 때 지난 실행의 일시정지만 있을 때 무엇을 보이는지다. 이 진행 표시는 창을 내려두고 받는 사용자에게 가장 값싼 신호라(users §1.3) 틀리면 "다 받았다"고 잘못 믿게 한다. 코드는 `crates/shell/src/dock.rs`(순수, Tauri 비의존)와 `app/src-tauri/src/status.rs`(1Hz 태스크)다.

## 결정

`DockMeter::tick(jobs, focused)`는 **배치 구성원** 기준으로 집계하고 바뀌었을 때만 `DockState { status, progress }`를 돌려준다(처음 호출은 늘 Some).

- 구성원 = 배치가 열린 뒤 한 번이라도 running·pausing·queued였던 작업 id. 배치는 그런 작업이 처음 보일 때 열린다.
- 배치 끝 = 구성원이 모두 completed·skipped·failed이거나 목록에서 사라졌을 때만. paused·interrupted 구성원이 있으면 배치는 열려 있다(모두 일시정지해도 같은 배치이고, 이어받으면 이어진다).
- 진행값 = 구성원 전체의 받은 합 ÷ 전체 합 × 100 내림, 100으로 캡. 완료는 받은 = 전체, 실패·멈춤은 마지막 받은 바이트와 그 전체. 전체를 모르는 구성원은 분자·분모에서 뺀다. 배치 안에서 내보내는 값은 직전 값보다 작아지지 않는다.
- 상태: running·pausing·queued가 있으면 Normal(일부가 실패해도). 없고 paused·interrupted가 있으면 Paused(failed가 함께 있어도 Paused가 이긴다). 배치 끝 + 실패 하나 이상 + 창 포커스 없음이면 Error(마지막으로 내보낸 값), 포커스가 오면 None으로 닫는다. 배치 끝 + 실패 없음, 배치 없음은 None. 전체를 아는 구성원이 없으면 Normal + 진행값 없음(Indeterminate는 쓰지 않는다).
- 호출 빈도는 `DOCK_PROGRESS_MIN_INTERVAL_MS`(1000) 이하의 1Hz 폴링이다. 배지는 v1에서 끈다(`set_badge_*` 호출 0개).

## 결과

- 바뀌는 곳: `crates/shell/src/dock.rs`(순수 집계), `app/src-tauri/src/status.rs`(1Hz 태스크, `DockStatus` → `ProgressBarStatus` 매핑, 첫 틱의 지우기는 OS로 보내지 않고 한 번이라도 칠한 뒤의 지우기부터 보낸다: Windows `ITaskbarList3` 호출이 호출마다 COM 객체를 만들기 때문), platform §8.2·§22 32.
- Error의 진행값은 마지막으로 내보낸 값이다. 포커스 중에 끝난 실패는 곧바로 None으로 닫는다.
- gate: `rust`(`dock.rs` 단위 테스트: 단조성, 한 작업 완료 순간 값이 튀지 않음, 전부 일시정지 → Paused, 다시 이어받으면 같은 배치, failed + paused → Paused, 배치 끝 실패 → Error → 포커스 → None, 크기 모름, 시작 시 paused만 → None), `tauri`(상태 매핑).
- 이 ADR이 platform §8.2 표를 구체화한다. 표와 다르면 이 ADR이 이긴다.

### 재검증 조건

- 실기에서 Dock·작업 표시줄이 퍼센트대로 차지 않거나 일시정지 노랑·실패 빨강이 틀리면(M9) 상태 매핑을 다시 본다. 확인: platform §21 M9(macOS·Windows), 대비 테마에서 숨겨져도 앱이 문제 삼지 않는지는 M13.
- 사용자가 "배치가 안 끝난 채 계속 노랑으로 남는다"고 느끼면(일시정지 구성원이 배치를 열어 둠) 일시정지 구성원의 처리를 다시 본다. 확인: D62 관찰과 첫 실사용 기록.

## 대안과 버린 이유

| 대안 | 버린 이유 |
|---|---|
| 지금 받는 작업만 합산한다(구성원 기준 없음) | 한 작업이 끝나는 순간 분자는 그대로인데 분모가 줄어 값이 튀거나 줄어든다 |
| 값이 줄어도 그대로 보인다 | 진행 막대가 뒤로 가는 것은 "고장"으로 읽힌다. 새 작업이 더해질 때의 감소만 흡수하는 장치로 충분하다 |
| `Indeterminate`로 전체 크기를 모르는 작업을 표현한다 | macOS·Linux에서 0% 파랑 막대로 보인다 |
| 일부 실패가 나면 바로 Error(빨강)로 바꾼다 | 일시적 실패 하나로 받는 중인 전체를 빨갛게 하지 않는다(README D37의 오류 어조 절제) |
| 배지(숫자)도 켠다 | Windows에는 오버레이 아이콘 에셋이 필요하고 v1 범위 밖이다 |
