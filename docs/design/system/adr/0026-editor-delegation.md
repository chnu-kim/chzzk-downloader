# 0026 맡기기: 본인 영상 제한을 채널 주인이 맡긴 채널로 넓힌다

상태: 채택(잠정)   날짜: 2026-10-16   관련: D37·D42·D43·D44·D52·D62·D63, §6-3·§6-7, ADR-0009·ADR-0025, `docs/design/features/delegation.md`, worker.md 구현 중 변경 105·106

## 맥락

지금 앱은 로그인한 채널의 영상과 클립만 받는다(ROADMAP "확정된 결정 › 본인 영상 제한", 셸 `OwnershipGate`, 공개 약속 문구 `notice.unofficial` 끝 문장 `app/src/lib/copy/ko.ts`·`worker/src/http/copy.ts`, DC6). 사용자 결정(2026-10-16, `docs/design/features/decisions.md` Q1·C1)으로 실제 사용자에 **스트리머의 편집자**가 들어왔고, 편집자는 남의 채널 영상을 받아야 한다. 설계는 `docs/design/features/delegation.md`(세 안 중 1안 맥락형 + 접붙인 여덟 가지)이고, Worker 쪽은 머지됐다(worker.md 구현 중 변경 105 저장소·106 웹·앱 API, `worker/src/store/delegation.ts`, `worker/src/http/copy.ts` 편집자 문구).

이 기능은 디자인 시스템의 세 가지를 건드린다(README §7.1).

- 4번 새 패턴: 설정 계정 그룹의 편집자 행, 막힌 카드의 다음 행동 한 줄, 지연 회수 토스트.
- 5번 [잠정] 항목: 새 상수 여섯, 용어집 "되돌리기" 자리 확장. 확인: 아래 재검증 조건.
- 3번 원칙의 예외: ADR-0025의 "게이트는 그대로다: 생방송도 본인 채널 판정을 한다. 별도 규칙이 없다"에 예외 하나가 생긴다.

## 결정

- **본인 영상 제한을 "로그인 채널 또는 그 채널 주인이 맡긴 채널"로 넓힌다.** 신뢰 수준과 판정 자리(셸 `OwnershipGate`, 클라이언트 정책·명분 수준)는 그대로다. ROADMAP의 그 행은 취소선 + 날짜 관례로 고쳤다(#112).
- **새 말은 용어집 행으로만 들인다**(content.md §4): 맡기다 · 편집자 · 맡은 채널 · 채널 주인 · 초대 주소 · [편집자 되기] · [편집자 빼기] · [편집자 그만두기] · [초대 취소] · "관리자 확인 기다리는 중". "허가"는 관리자의 사용 허가 한 뜻으로 남기고(D43, W1) 위임에 쓰지 않는다. "위임·권한·공유·수락·승인·링크"는 화면에 쓰지 않는다.
- **막힌 카드의 동작은 새 라벨 없이 기존 [다시 불러오기]다.** 누르면 늘 로그인 서버에 맡은 채널을 물은 뒤 영상을 다시 불러온다. "다시 확인"은 버튼 허용 목록(content.md §5) 밖이라 쓰지 않고, 그래서 허용 목록도 고치지 않는다.
- **용어집 "되돌리기" 자리에 [편집자 빼기]를 더한다**: "되돌리기 토스트의 버튼에만(목록 지우기·편집자 빼기)". 같은 뜻(방금 한 일 무르기)·같은 수단(지연 실행 토스트, D37)이라 W1의 "한 낱말 두 뜻"이 아니다. [편집자 빼기]는 가역이라 확인 창이 없고, 토스트가 닫힐 때(타이머·[×]·대기열 교체) 회수가 확정된다. `restore` API는 없다.
- **ADR-0025 게이트 줄의 예외**: v1은 맡은 채널의 **생방송**을 열지 않는다(사용자 결정 L-D1 (A)). 판정에 맡은 채널이 생기지만 생방송에는 쓰지 않는다. 본인·관리자 판정은 그대로다. D63의 "본인 채널 게이트 그대로"도 생방송에는 여전히 참이다.
- **늘 보이는 새 요소는 최소로 둔다**(UX 기준 "숨겨지지 않으면서 튀지 않게"). 앱에는 설정 행 하나, 그리고 맡은 채널이 있을 때만 행 하나를 더 두고, Worker에는 초대 페이지와 완료 페이지만 둔다. 관리 화면에는 거부된 시도 행의 꼬리표 하나만 더한다. 배너·대화상자·메뉴 항목·랜딩 블록·Badge는 더하지 않는다. 웹에는 복사 버튼을 두지 않는다(D52). 그래서 초대 주소는 앱에서 만들고 복사한다.
- **상수 여섯은 ADR-0009 묶음에 등록한다.** 초대 7일, 편집자 10명, 맡은 채널 20개, 청구 보존 30일, 회수 행 보존 30일, 완료 창 2분이고 모두 Worker `store/delegation.ts`에 있다. 셸의 판정 직전 자동 확인 간격(5분)은 ①-4 셸 항목이 머지된 뒤 같은 묶음에 덧붙인다.
- **D 번호는 새로 두지 않는다.** 이 결정은 결정 표의 값을 뒤집지 않는다. D37·D42·D43·D44·D52·D63은 그대로이고, 바뀌는 것은 ROADMAP 결정 하나와 용어집 행이다. 결정 표 값이 바뀌는 일이 생기면 그때 D63 다음 번호를 받는다.

### 재검증 조건

- **발견성·수락 방식**: D62 UT8(스트리머가 설정 행만으로 맡기는 길을 찾는가)과 UT9(로그인 = 수락에 놀라는가, 열려 있던 거부 카드에서 [다시 불러오기]를 찾는가)를 본다. 이 둘은 적용 전 앱에 기능이 없어 기준선 회차가 없다. 그래서 이 기능이 들어간 뒤의 회차끼리만 합산하고, 두 회 이상·회당 3명일 때만 판정 근거로 쓴다(governance §6.2). 한 회만 돌리면 "축소한 시험"으로 적고 확정 근거로 쓰지 않는다. 3명 중 2명 이상이 설정 행을 못 찾으면 행 위치를 다시 정한다. 2명 이상이 수락에 놀라면 로그인 뒤 확인 단계를 더한다. 어느 쪽이든 새 ADR을 쓴다.
- **상수**: 여러 채널을 맡는 편집자가 흔한지 사용자 인터뷰로 본다(`delegation.md` §18-2). 결과는 ADR-0009 행 값으로 고친다.
- **관리 꼬리표**: 관리자가 "누가 누구의 편집자인가"를 물으면 위임 관계 표를 더한다(`delegation.md` §18-8). 확인 방법은 운영 기록이다.
- **생방송**: 녹화 중 회수 처리(⑤ O-4)를 정하면 L-D1을 다시 연다. 그때 이 ADR의 ADR-0025 예외를 거두는 새 ADR을 쓴다.

## 대안과 버린 이유

| 대안 | 버린 이유 |
|---|---|
| 2안 관리형: 설정 5번째 절 "편집자"와 랜딩 블록, 관리자 표 | 발견성은 같지만 늘 보이는 요소가 가장 많다. 설정 화면에 비밀 주소가 머문다(`delegation.md` §1.1) |
| 3안 초대 주소형: 웹에서 초대를 만든다 | 스트리머의 길이 브라우저로 꺾여 다섯 단계가 되고 로그인을 두 번 한다. 웹에는 복사 버튼이 없다(D52) |
| 위임에 "허가"를 쓴다 | 관리자 허가와 한 낱말 두 뜻(W1)이 된다 |
| 막힌 카드에 [다시 확인]을 둔다 | 버튼 허용 목록 밖의 새 낱말이다. [다시 불러오기]가 결과(카드를 다시 판정해 다시 그림)와 맞는다 |
| [편집자 빼기]에 확인 창을 둔다 | 가역 동작이다. 확인 창보다 되돌리기가 맞다(patterns §4, D37) |
| 위임 = 허가(편집자도 허가 목록에 자동으로 넣는다) | 허가는 관리자가 따로 한다는 ROADMAP 결정을 뒤집는다. 가+(관리자 [허가] 때 위임이 함께 완성)로 마찰만 줄였다 |
| 맡은 채널의 생방송을 v1부터 연다 | 회수 뒤에도 녹화 하나가 몇 시간씩 새 내용을 받아 회수 지연 상한이 깨진다(사용자 결정 L-D1) |
| 결정 표에 새 D 번호를 둔다 | 결정 표의 값을 뒤집지 않는다. 바뀌는 것은 ROADMAP 결정 하나와 용어집 행이다 |
