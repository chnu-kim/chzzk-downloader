# 0031 생방송 녹화 마치기 확인(D8): 되돌릴 수 없지만 지우지 않는 동작은 neutral, 생방송에 일시정지 없음

상태: 채택(잠정)   날짜: 2026-11-01   관련: D68, D63, D36, D1, D5, ADR-0005, ADR-0025, ADR-0026, content.md §4·§5.3·§15.1, patterns.md §4·§5.2, app.md 127

## 맥락

사용자가 생방송 녹화에서 "일시정지"가 보이는 것과, 방송이 끝난 뒤 멈춘 녹화를 [이어받기]하면 막다른 길에 빠지는 것을 짚었다(2026-11-01). 진단은 둘이었다.

- 일시정지 어휘와 길이 생방송에 남아 있었다: 셸 `pause`가 생방송을 받아 `Finish`로 바꿔 주는 우회, 대기 중 생방송의 `pause`·`stop_job`이 `Paused`를 만드는 길, `End::Cancelled`+`Finish`가 `Paused`가 되는 방어 코드, 멈춘 생방송의 상태 문구 "일시정지됨", 창 닫기(D1)·업데이트(D5) 본문의 "일시정지돼요". ADR-0025는 "일시정지는 생방송에 없다"고 정했는데 길이 닫히지 않았다.
- 막다른 길: `resume_job`이 소유 게이트에서 live-detail을 조회하고, 방송이 끝났으면 `NotLive`로 거부해 조회 없이 끝내는 코어의 마무리 길까지 가지 못했다. 이것은 코드 수정(게이트가 생방송의 채널을 컨텐츠에서 읽는다)이고 이 ADR의 결정은 아니지만, ADR-0025 "게이트는 그대로다"와 app.md 77을 보충하므로 여기에 적는다.
- [녹화 마치기]는 되돌릴 수 없는데 확인이 없었다. [취소]에는 D2가 있다.

디자인 시스템의 두 가지를 건드린다(README §7.1): 새 대화상자 D8(patterns §5.2 표 한 종 추가), D36 "되돌릴 수 없으면 danger"의 정밀화.

## 결정

- **생방송은 어느 경로에서도 `Paused`가 되지 않는다.** 셸 `pause`는 생방송이면 상태와 무관하게 `invalidInput`으로 거부하고, 대기 중 생방송의 `stop_job`은 아무것도 하지 않으며, `End::Cancelled`+`Finish`는 생방송이면 `Interrupted`로 한다. 옛 `jobs.json`의 `Paused` 생방송은 읽기만 그대로 받고(마이그레이션 없음) 화면은 끊긴 녹화 어휘로 그린다. 상태 줄은 "녹화 끊김" 또는 "녹화 끊김 · {bytes} 받음", 본문은 `job.live.partial.body` 그대로, 버튼은 [이어받기][취소]다.
- **방송이 끝난 뒤의 [이어받기]는 조회 없이 받은 부분까지 저장한다.** `admit_job`은 컨텐츠가 `ContentRef::Live { channel_id }`이면 채널을 조회하지 않고 컨텐츠의 채널로 판정한다(코어가 같은 값으로 live-detail을 부르므로 응답의 채널 = 요청한 채널). 로그인 확인·`classify`·거부 시 `note_channel`은 그대로 지난다. `.part`가 없는 생방송의 `NotLive` 실패는 job 자리에서 [다시 시도]가 아니라 [다시 녹화]를 준다(켜지면 다른 방송을 옛 제목·시각으로 받게 되기 때문).
- **D8 녹화 마치기 확인**: 작업 행의 [녹화 마치기]는 받은 바이트가 0보다 클 때만 대화상자를 연다(0이면 잃는 것이 없어 바로 마친다. D2의 0바이트 규칙과 같다). 왼쪽 [녹화 마치기](`neutral`), 오른쪽 [계속 받기](채움·Enter·첫 포커스, 기존 `dialog.cancel.keepRunning` 재사용), Esc = 닫기. "다시 묻지 않기"는 없다.
- **비가역이지만 지우지 않는 동작은 `neutral`이다.** D36의 "되돌릴 수 없으면 빨간 글자"를 "되돌릴 수 없고 **무언가를 지우면** 빨간 글자"로 정밀화한다. 녹화 마치기는 받은 만큼 저장하므로 지우는 것이 없다. `danger`는 파일·데이터를 지우는 D2·D7에만 둔다. 이 구분이 없으면 빨간 글자가 "지운다"가 아니라 "되돌릴 수 없다"를 뜻하게 되어 D2·D7의 경고가 흐려진다.
- **행 버튼 [녹화 마치기]에 말줄임표를 붙이지 않는다.** [취소]의 예외(content §5.2: 잘린 제목과 헷갈림)를 "작업 항목의 버튼"으로 넓힌다. 확인 여부는 대화상자가 알린다.
- **D1·D5 본문은 받는 중인 것이 전부 생방송이면 "일시정지"를 말하지 않는다.** 섞이면 기존 본문, 전부 생방송이면 `dialog.closeLive.allBody`·`dialog.updateLive.allBody`, D5는 생방송이 없을 때만 기존 `dialog.update.body`다. 프런트가 `jobs.state`에서 센다(DTO·command 변경 없음).
- **구현 선택(명세와 다른 점)**: 본문은 `{size}까지 받았어요. 받은 만큼 저장하고 녹화를 끝내요. 되돌릴 수 없어요.`(세 문장)다. 명세의 `지금까지 받은 {size}를 …`는 변수 뒤 조사 금지(DC3)에 걸려 D2 본문 꼴로 바꿨다. 실행 라벨 키 `dialog.stopLive.confirm`은 만들지 않고 값이 같은 `action.stopRecording`을 재사용한다(값이 같은 키가 둘이면 DC11이 막는다). 리뷰 반영: 영상 조각이 없는 끊긴 생방송(일시정지됨·중단)은 [이어받기] 대신 [다시 녹화]를 주고 B1 모두 이어받기에서 뺀다(지금 켜진 다른 방송을 옛 제목·시각 파일로 녹화하지 않게, app.md 127 ⑥). D8은 받는 중이면 녹화 길이가 0보다 클 때만 연다(init만 받았으면 저장할 것이 없다, ⑦).

### 재검증 조건

- **D62 과업**: 녹화 중 멈추려는 사람이 어느 버튼을 누르는지, 확인 창을 읽고 뜻("받은 만큼 저장하고 끝낸다")을 말하는지 본다. [계속 받기]를 눌러 녹화를 이어 가려는 사람이 [녹화 마치기]를 잘못 누르면 neutral 구분을 다시 연다.
- **실기**: 방송이 끝난 뒤 앱을 다시 켜고 [이어받기]로 받은 부분까지 저장되는지, `.part`가 없을 때 [다시 녹화]가 카드로 이어지는지 확인한다.

## 대안과 버린 이유

| 대안 | 버린 이유 |
|---|---|
| 확인 없이 둔다 | 되돌릴 수 없고 오누름이 방송 한 편의 손실이다. D2와 기준이 어긋난다 |
| 실행 쪽을 `danger`로 | 지우는 것이 없다. 빨간 글자가 D2·D7의 "지운다" 경고를 흐린다 |
| 받은 것이 0이어도 확인 | 잃는 것이 없다. 결과는 `NothingRecorded` 실패 + [다시 시도]다 |
| `pause`가 생방송이면 `Finish`로 바꿔 준다(옛 우회) | 확인 없이 되돌릴 수 없는 마무리가 된다 |
| `NotLive` 실패에 [다시 시도] | 꺼진 동안 영원히 실패하고, 켜지면 다른 방송을 옛 제목·시각 파일로 받는다 |
| 게이트에서 live-detail을 그대로 조회 | 방송이 끝났으면 `NotLive`로 거부해 받은 부분을 저장할 길이 막힌다 |
| "다시 묻지 않기" | 비가역 확인에는 허용하지 않는다(patterns §4, `G-INTER-CF5`) |
