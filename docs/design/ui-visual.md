# 치지직 다운로더 — 시각 설계 (ui-visual.md)

`docs/design/app.md` §8(화면)·§9(문구)·§10(컴포넌트)의 시각 층이다. 이 문서가 정한 값은 `app/src/styles/tokens.css`에 토큰으로 있고 `app/src/app.css`가 한 번 가져온다. 컴포넌트는 토큰만 쓰고 색·간격 리터럴을 쓰지 않는다. 대비 수치는 `app/src/styles/tokens.test.ts`가 토큰 파일에서 직접 계산한다.

대상: 스트리머 한 사람과 지인 몇 명, 비기술자. 하루에 몇 번 주소를 붙여넣고 받는 작은 도구. 창은 기본 960x700, 최소 720x520, OS 라이트·다크를 따른다.

---

## 0. 방향

**"조용한 받기 트레이."** 이 앱이 하는 일은 하나 — 주소를 받아 파일이 되는 것을 지켜보는 것이다. 화면의 유일한 주인공은 **진행 중인 작업의 막대와 숫자**이고, 나머지는 전부 그것을 방해하지 않도록 뒤로 물러난다.

세 가지 선택이 이 앱을 다른 다운로더·범용 템플릿과 다르게 만든다.

1. **종이 위의 트레이.** 창 바탕은 흰색이 아니라 종이 같은 차가운 회색(`--bg`)이고, 입력·카드·목록 항목만 흰 면(`--surface`)이다. 면과 면 사이는 그림자가 아니라 1px 선으로 나눈다. 그림자는 떠 있는 것(대화상자·메뉴·토스트)에만 있다. "카드 더미" 느낌을 피하고, 눈이 흰 면 = 만질 수 있는 것으로 읽게 한다.
2. **왼쪽 레일 하나로 상태를 말한다.** 작업 항목의 왼쪽 가장자리에 3px 레일이 있고, 색이 상태(받는 중 청록·멈춤 회색·실패 빨강·완료 초록)를 말한다. 레일은 색 외에 아이콘·문구와 함께 가므로 색각 이상에서도 정보가 빠지지 않는다. 항목 전체를 색으로 칠하거나 배경을 바꾸지 않는다.
3. **숫자가 글자보다 또렷하다.** 진행률 퍼센트·크기·속도·남은 시간은 고정폭 숫자(`tabular-nums`)에 `--fg`, 그 사이 설명("받는 중", "남음")은 `--fg-muted`다. 사용자가 보고 싶은 건 "58%, 2분 18초"이지 "받는 중"이라는 단어가 아니다.

하지 않는 것: 치지직 브랜드 색·로고, 번들 글꼴, 그라데이션, 모든 면에 같은 그림자, 대문자 눈썹 라벨, 장식용 번호, 섹션마다 등장 애니메이션.

### 1.3 색 규칙

- 상태는 늘 세 겹이다: **색(레일·막대) + 아이콘 + 문구.** 색 하나만으로 말하는 곳이 없어야 한다.
- 면을 색으로 칠하는 건 `*-soft` 넷뿐이고, 그 위 글자는 `--fg` 또는 같은 계열 진한 색(`--danger` 위 `--danger-soft`처럼)만 쓴다.
- 배지는 테두리 1px + 글자만(면 투명). 성인 배지만 `--danger` 테두리·글자.
- 링크 같은 글자(설정 폴더 열기 등)는 `--accent`, 밑줄은 hover에서만.

## 2. 글자

### 2.1 글꼴 스택 (번들 없음)

```
--font-sans: system-ui, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", "Noto Sans CJK KR", "Segoe UI", sans-serif;
--font-mono: ui-monospace, "SF Mono", Menlo, Consolas, "Cascadia Mono", "D2Coding", monospace;
```

- macOS: `system-ui`가 한국어를 Apple SD Gothic Neo로 폴백한다. 명시해서 순서를 고정.
- Windows: `system-ui`는 Segoe UI → 한글이 없어 Malgun Gothic으로 떨어진다. `Malgun Gothic`을 앞에 둬 영문과 한글의 높이 차이를 줄인다.
- Linux: Noto Sans KR / Noto Sans CJK KR 둘 중 설치된 것.
- 모노는 쿠키 값 입력칸(`SecretField`)과 "문제 보고용 정보"에만. 숫자 표시에는 쓰지 않는다(본문 글꼴 + `tabular-nums`).

### 2.2 크기·굵기

본문 14px, 최소 12px. rem 기준(`:root` 14px).

| 토큰 | px | 굵기 | 쓰는 곳 |
|---|---|---|---|
| `--text-xs` | 12 | 500 | 배지, kbd, 그룹 헤더 숫자, "저장될 이름:" |
| `--text-sm` | 13 | 400 | 상태 줄, 보조 설명, 메뉴, 최근 VOD 제목 |
| `--text-md` | 14 | 400 / 500(버튼) | 본문, 입력, 버튼, 항목 제목 |
| `--text-lg` | 16 | 600 | 카드 제목, 대화상자 제목, 헤더 앱 이름 |
| `--text-xl` | 19 | 600 | 설정 제목, 빈 상태 제목 |
| `--text-hero` | 22 | 600 | (선택) 넓은 창에서 진행 중 항목의 퍼센트 |

- 행간: 본문 1.5, 제목 1.3, 설명 문단 1.65. 16px 이상은 자간 -0.01em.
- 굵기는 400·500·600 세 단계만. 700은 쓰지 않는다(Malgun Gothic은 700이 번져 보인다).
- 숫자는 `.tnum`(`font-variant-numeric: tabular-nums`). 진행률 줄 전체에 건다.
- 긴 제목: `word-break: keep-all; overflow-wrap: anywhere`(전역). 항목 제목은 1줄 말줄임 + `title`, 카드 제목은 2줄(`-webkit-line-clamp: 2`).
- 눈썹 라벨·대문자·장식 번호 없음. 섹션 제목은 `--text-md` 600 + 아래 1px 선이 아니라 **위 여백으로** 구분한다.

## 3. 간격·모서리·높이

- **간격** 4px 기준: `--space-1`(4) `-2`(8) `-3`(12) `-4`(16) `-5`(20) `-6`(24) `-8`(32) `-10`(40) `-12`(48).
  - 창 가장자리 `--gutter` 16(720)·`--gutter-wide` 24(840 이상). 카드 안 패딩 16. 항목 안 패딩 12 16. 섹션 사이 24. 폼 행 사이 12.
- **크기**: 헤더 48, 컨트롤 36(입력·버튼), 작은 컨트롤 28(항목 안 버튼), 아이콘 20/16, 진행 막대 6, 레일 3. 본문 최대 폭 896(`--content-max`).
- **모서리**: 4(kbd·진행 막대) · 6(배지·메뉴 항목) · 8(버튼·입력·카드·항목) · 12(대화상자·토스트) · 999(스위치·스피너). 계층이 다른 것은 모서리가 다르다 — 모두 8이 아니다.
- **높이(그림자)**: 세 단계만, 떠 있는 것에만. `--shadow-menu`(메뉴) < `--shadow-toast`(토스트) < `--shadow-dialog`(대화상자). 다크에서는 그림자 대신 1px 밝은 안쪽 선이 경계를 만든다(토큰에 포함). 카드·항목·배너는 그림자 없음.

## 4. 움직임

원칙: **사용자의 행동에 답하는 움직임만.** 페이지 로드·섹션 등장 애니메이션 없음. `prefers-reduced-motion: reduce`면 모든 `--dur-*`가 0ms가 되어 transition이 즉시 끝나고, 아래 "꺼지는 것"은 CSS에서 `@media`로 직접 끈다.

| 토큰 | 길이 | 쓰는 곳 |
|---|---|---|
| `--dur-fast` 120ms, `--ease-out` | hover·active 색, 스위치 손잡이, 라디오 점 |
| `--dur-base` 180ms, `--ease-out` | 메뉴·토스트 등장(opacity + 4px 이동), Disclosure 펼침(height) |
| `--dur-slow` 240ms, `--ease-out` | 대화상자(scrim opacity + 상자 scale .98→1), 카드 접힘 |
| `--dur-highlight` 1000ms | 새 항목 강조: `--accent-soft` 바탕이 투명으로 사라짐 |

진행 막대 `width`는 **transition 하지 않는다**(250ms 틱마다 자연스럽게 움직이고, 끊긴 뒤 이어받을 때 "되감기"처럼 보이지 않게). 대신 `transform: scaleX`도 쓰지 않고 width를 그대로 둔다 — 6px 막대라 리플로우 비용이 없다.

**reduced-motion이면 끄는 것**: 스켈레톤 반짝임(정지된 `--surface-2`), 링크 갱신 줄무늬 이동(정지된 줄무늬는 남긴다 — 패턴 자체가 정보), 스피너 회전(회전 대신 점 셋이 교대로 불투명해지는 것도 끄고, 정지 링 + "불러오는 중" 문구), 새 항목 강조(즉시 사라짐).

## 6. 화면 레이아웃

창 안쪽 구조는 셋이다: 고정 헤더(48) → 배너 자리(있을 때만) → 스크롤되는 본문. 본문은 `--content-max`(896)까지 늘고 그 뒤로는 가운데 정렬, 좌우 바탕색이 남는다. 본문 안은 **입력 영역**(위, 접힘)과 **다운로드 목록**(아래, 남는 높이 전부)의 두 덩어리다. 왼쪽 정렬이 기본이고, 가운데 정렬은 빈 상태 문구와 대화상자뿐이다.

### 6.1 홈, 빈 상태 — 720x520

## 9. app.md와의 조정

- app.md §10의 토큰 목록(`--bg … --focus`)에 `--surface-raised --border-strong --scrim --fg-faint --accent-hover --accent-fg --danger-hover --danger-soft --danger-fg --warning-soft --success-soft` 와 글꼴·간격·모서리·그림자·움직임·z 토큰을 더했다. 이름이 겹치는 것은 뜻이 같다.
- 토큰은 `app.css`가 아니라 `styles/tokens.css`에 두고 `app.css`가 `@import`한다(§10 "app.css의 커스텀 프로퍼티"를 파일 하나로 분리). Vite가 빌드 때 합치므로 CSP·요청 수에 영향 없다.
- 작업 항목의 왼쪽 상태 레일(3px)은 §10의 "상태별 표현"에 더한 것이다. 실패 항목의 `danger` 테두리는 유지한다.
- 설정 화면에 "동시에 받는 영상 수"(1~3)·"앱을 열면 멈춘 다운로드를 자동으로 이어받기" 두 행을 §8.7 그림에 더했다(§16 답변). 문구 키는 `settings.parallel`·`settings.parallel.help`·`settings.autoResume`·`settings.autoResume.help`로 §15-12 copy deck에 넣는다.
- UrlBar의 드래그 오버·클립보드 제안 상태(§6.4)는 §8에 그림이 없던 것이다. 문구 키 `url.dropHere`(여기에 놓으면 불러와요)·`url.clipboard.title`(복사한 주소가 있어요)·`url.clipboard.load`(불러오기)를 더한다.
- `data-theme="light|dark"` 속성으로 OS 설정과 무관하게 테마를 고정할 수 있다(테스트·스크린샷용). 사용자 설정 항목은 아니다.
